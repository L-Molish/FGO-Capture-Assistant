FGO抓包助手 v2.1.1 使用说明

Windows 单文件程序，支持 MuMu 安卓 15 ROOT 实例上的 FGO 国服、日服登录抓包、抽卡统计和迦勒底数据报告。抓包入口统一为 mitmproxy（默认）与 Reqable（原有流程），mitmproxy 的出口由“检查环境”按实际能力识别。

一、使用

1. 把 FGO抓包助手-v2.1.1.exe 放到可写文件夹（不要放在需要管理员权限的目录），无需安装 Python。
2. 选择国服或日服，绑定 MuMu 路径并选择目标模拟器实例。
3. 首次使用点击“初始化环境”：需要 MuMu 安卓 15 ROOT、KernelSU 和对应区服游戏。程序会配置 Reqable 证书，并把本程序的 mitmproxy 证书并入同一个 KernelSU 模块，重启后核验系统与 Conscrypt 两处证书库；Reqable 证书保留。
4. 点击“检查环境”，界面会给出简要结论和逐项检查。未知 VPN 包名本身不会使检查失败，而会显示“待验证”，再按后续能力尝试。
5. 选择抓包方式：mitmproxy（自动选择出口）或 Reqable（原有方式），点击“开始抓包”，按提示在游戏中点击登录。
6. 成功后从剪贴板或结果文件导入统计页；国服结果在 results/，日服在 results/JP/。

二、环境检查与自动选路

- 国服：固定使用电脑网络；仍检查游戏到抓包代理的连通性，不因国服忽略活动 VPN。
- 日服、无活动 VPN：使用电脑网络。TUN 沿用现有路由；电脑有明确可用的 HTTP/HTTPS 系统代理时，mitmproxy 上游显式指向该代理；两者都没有时直接出站。
- 日服、有活动 VPN/加速器：不按包名准入。程序先发现并验证本地 HTTP 代理端点；端点地址贯穿发现、去重、探测、保存和转发。通配监听按实际回环 127.0.0.1 连接，::ffff:127.0.0.1 归一为 127.0.0.1，其它回环地址保留原值。ADB forward 只能连接设备 127.0.0.1:port，无法保持的地址会明确说明并回退，不会静默改写。
- 没有可用 HTTP 端点时：若能读到日服游戏 UID 且中继工具齐全，进入游戏 UID 中继路径。运行时会依次确认：中继监听成功 → 接受 CONNECT → 出站 TCP/TLS 成功 → 最终有效登录响应。CONNECT 返回 200 只表示中继接受了请求，不等于目标服务器或加速器链路已经连通；程序只有在 TLS 握手完成后才把中继出站判定为成功。
- 未知 VPN 包名不会直接导致“尚未适配”。只有缺少游戏 UID 或中继工具时，才会以明确阶段报错。
- 只支持明确识别的 HTTP/HTTPS 系统代理；PAC 或只有 SOCKS 时会说明未接入，不会假装已连接。
- 自动发现不到时，可在程序目录 settings.json 填写 "device_proxy": "127.0.0.1:端口"，或设置环境变量 FGO_DEVICE_PROXY；该端点仍会先做 HTTP CONNECT 验证，不会直接采用。
- 识别的是实际 VPN CONNECTED 会话，不是应用进程是否存在。程序不关闭或重配电脑 Clash/TUN，不切换节点、模式或全局规则。

开始抓包时会重新识别一次当前出口，并与上次“检查环境”的结果比较；配置有变化时会写入运行日志，再按新的能力结果选路。

三、抓包前的准备

- 使用模拟器内加速器时，请先打开加速器并加速 FGO，进入游戏标题画面后再点“开始抓包”。程序不会代启动游戏或加速器；挂好代理后会提示点击登录。
- 使用电脑网络时，程序会启动游戏并等待登录。
- 不要在挂好抓包代理后无必要地强制重启游戏；如果游戏异常退出，先确认加速器仍处于加速状态，再从加速器卡片启动到标题画面。

四、抓包证书（CA）

- 本机 CA 由程序自动管理，保存在程序所在目录的 mitm-confdir。普通用户不需要设置环境变量；FGO_MITM_CONFDIR 仅作为可选覆盖。
- 首次安装由“初始化环境”完成：程序生成本机 CA，把它并入现有 Reqable 证书模块，通过 KernelSU 安装并重启，再核对 /system/etc/security/cacerts 与 /apex/com.android.conscrypt/cacerts 两处。Reqable 证书不会被替换。
- 生成模块时会检查 post-fs-data.sh 是否同时合并两处证书库；只在缺失时替换为已验证的双库脚本，module.prop、Reqable 证书及其它模块文件保持不变。
- 核验失败时会分别说明系统证书库缺失、Conscrypt 证书库缺失、内容不一致或读取失败，并给出模块的实际启用状态。
- 程序不打包测试 CA 私钥、账号数据或原始抓包，也不安装 Windows 根证书。
- 如果“检查环境”提示抓包证书未安装，请点击“初始化环境”。

五、停止与恢复

- 点击“终止”、抓包失败或下次启动时，程序只恢复自己修改或创建过的内容：设备代理五键、ADB forward/reverse、设备内的中继目录。不会用整张 iptables 表哈希作为恢复成功的条件。
- 如果用户中途自行改了配置，程序不会覆盖。
- 程序不会清除游戏数据或缓存、不迁移账号、不重装游戏；不会为选路功能修改 hosts、iptables 或策略路由；不会改变 ROOT/KernelSU 状态。
- 抓包结束后可用程序状态记录与本机检查确认：设备代理为 null、没有本程序的 forward/reverse、没有残留中继目录和 mitmproxy 进程。

六、结果与统计

- 成功后可复制到剪贴板，或直接用结果文件导入。国服结果在 results/，日服在 results/JP/。
- 抓包文件旁边的 .origin 是区服校验文件；把日服结果移动到其它位置供本助手统计时，需要同时移动对应的 .origin。导入 Chaldea 只需原始响应 JSON。
- 统计使用程序内置的国服/日服资料快照，不依赖网络即可读取已收录的抓包。
- 点击统计页的“更新统计资料”可用现有资料更新机制取得最新公开资料，并在后续读取时优先使用较新的本地快照。
- v2.1.1 更新了内置日服资料：此前读取 2026-11-04 的日服抓包时出现 1 条未知图鉴记录，查明是新增的 4 星礼装（servantEquip）记录，不是从者；旧资料快照没有把它列入 ignored_ids。更新后未知从者记录为 0，五星数、抽数、福袋扣除、出货率和报告可正常构建。没有忽略未知项、手工凑数或跳过校验。
- 若公开资料仍未收录某条记录，程序会保留准确提示，不强行显示可能错误的出货率；这不阻塞已完成的抓包功能。
- 抓包和统计在本机完成。results、captures、diagnostics、设置和证书可能含个人信息，请勿公开分享。

- 日服 FlClash：自动选路、最终打包 EXE 的完整抓包与解析、退出清理。
- 日服电脑关闭 TUN、仅保留系统代理：完整抓包，mitmproxy 上游确认是 127.0.0.1:7897，测试后恢复 TUN。
- 日服无 VPN / 电脑系统代理的识别检查。
- 国服：选路逻辑与检查项（本轮未重新执行国服完整抓包，沿用既往验证）。
- biubiu：游戏 UID 中继链路沿用既往实机验证；本轮未重新运行 biubiu 抓包。

biubiu、FlClash 和 com.etalien.booster 是实测样本，不是品牌准入白名单。程序按能力复用本地 HTTP 代理与游戏 UID 中继，不因未知包名直接拒绝；这不表示所有加速器或 VPN 均已实测兼容。其它 Clash 客户端、UU、OurPlay 等仍需各自验证。

未适配或未验证：

- 其它 Clash 客户端的完整登录抓包。
- UU、OurPlay 等其它加速器的完整登录抓包。
- 只有 PAC 或只有 SOCKS 的电脑系统代理（会说明未接入，不会假装已连接）。
